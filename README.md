# Oasis 予測ツール v2（2026/07/27 大型アプデ対応）

Discordゲーム「おあしすっち」のレースを予測し、**3連単の買い目と口数**を
資金管理つきで提案するアプリです。ベットログが残るので、予測と実測を後から
答え合わせできます。

ローカル（`streamlit run`）でも、**Streamlit Community Cloud** でも動きます。
Cloud で動かす場合、学習ログはリポジトリの `logg/`、ベットログは Google
スプレッドシートに置きます → **[DEPLOY.md](DEPLOY.md)**

---

## v2 で何が変わったか

2026/07/27〜07/28 のアップデートで、ゲームの中身が予測モデルの前提ごと変わりました。

| ゲーム側の変更 | 旧版で起きること | v2 の対応 |
|---|---|---|
| パッシブが**2枠**に（07/27） | `脳筋 / パワー大アップ` を1個の未知スキルとして扱い、両方とも無視 | 2枠を正しく分解して両方を特徴量に |
| 新パッシブ**17種追加**（計35種） | 全部「未学習」で効果0 | 35種すべてカタログ化。数値が分かるものは実数値、残りは実ログから推定 |
| **スコアがタイム基準に変更**（07/28） | スコアの桁が距離ごとに激変（短距離 ~250 → ~1700）。旧データで学んだ回帰が壊れる | 学習ターゲットを「**レース内で中心化した log スコア**」に変更。スケール不変なので式が変わっても壊れにくい |
| 出走 **16頭**・3連単は**8頭以上**のみ | 想定外 | 頭数チェックと警告を追加 |
| 3連単は 1レース合計 **20口**まで／単勝は合計 **100口**（1口 1,000 rrc） | 3連単のみ対応・1口10,000固定 | 単勝の推奨（任意）を追加。合計口数の上限も反映。1口の単位は購入画面から自動検出 |
| 単勝は控除0%の純パリミュチュエルで**プール額が非公開** | — | 少額の試し買い前後のオッズ変化から**プールを実測**し、希薄化込みで配分を計算 |
| **パッシブの数値が明記**された（07/27） | 攻略本由来の古い倍率をハードコード | 全35種の**公式の数値**を内蔵。説明文からの自動読み取りにも対応 |
| 同族嫌悪＝同じ**成体種**が出走していると×1.2 | 常時一定の倍率として扱う | 出走表の成体種を見て**発動する馬にだけ**適用 |

### 精度（実ログでのバックテスト・07/28以降の31レース）

| | レース内順位相関 | 1着的中 |
|---|---|---|
| 旧版（RandomForest・旧式データ学習） | 0.70 | 29% |
| v2（構造化リッジ・パッシブ数値なし） | 0.865 | 71% |
| **v2（公式35種の数値を全面反映）** | **0.916** | **84%** |

学習データ全体（34レース）に対する OOF 評価では 順位相関 0.926 / 1着的中 94%。
「実際に起きた3連単にモデルが付けた確率」は旧版の30倍以上で、買い目の期待値計算は
この確率がそのまま効くため、影響は非常に大きいです。

「実際の3連単に付けた確率」が10倍以上になっています。買い目の期待値計算は
この確率がそのまま効くので、影響は非常に大きいです。

### モデルの中身（v2）

- **ターゲット**: `log(score) − そのレースの log(score) 平均`
  レース単位の水準（距離・馬場・地面・その日の全体的な速さ）が自動的に消えるため、
  **ゲーム側の計算式が変わっても比較可能**なまま残ります。今回のような
  「スコアの桁が変わる」アップデートに強いのが最大の狙いです。
- **特徴量**: `距離 × log(実効スピード / 実効パワー / 実効スタミナ)` の交互作用、
  コンディション、数値が未取得のパッシブのダミー（＋距離交互作用）。
  「実効」＝パッシブの倍率を掛けた後の値です。
- **モデル**: リッジ回帰。α は**レース単位のクロスバリデーション**で自動選択。
  新式のデータが34レースしかない状況でも壊れないよう、木モデルではなく
  正則化つきの線形モデルにしています。
- **σ（着順のブレ幅）**: 「実際に起きた1〜3着の並びが最も出やすくなる σ」を
  自動で探索します。旧版は残差の標準偏差をそのまま使っていて過大でした
  （予測1着的中32% に対し実測69%）。
  ただし学習レースがまだ34件しかなく、σを小さくしすぎると買い目が絞られて
  過剰投資になるため、**安全係数（既定1.25）を掛けて弱気側に倒しています**。
  サイドバーで調整できます。ログが貯まって校正チェックが安定してきたら
  1.0 に近づけると期待値が上がります。
- **パッシブは「ゲームが明記した実数値」を使います**。購入画面の説明文
  （例:『スピードが35%上昇する代わりに、スタミナが10%低下する。』）を貼り付けると
  自動で数値を読み取り、`passive_spec.json` に保存して次回以降の予測に使います。
  スピード×1.35 のような倍率は**実効ステータスに直接畳み込む**ので、
  少ないログでも係数を推定する必要がなくなり、精度が上がります。
  数値が未取得のスキルだけ、従来どおり実ログの回帰で効果を学習します。
- **区間限定スキル**（例: ロケットスタート = 序盤のみスピード+12%）は
  発動率（序盤/中盤/終盤 なら 1/3、『20m以内にいる間』なら 0.5、
  『追い抜かれた直後の100mのみ』なら 0.1 など）を掛けて部分的に効かせます。
  実ログで発動率を一律 0.5〜1.5倍に振っても結果はほぼ変わらないので、
  この見積もりの粗さは実害になりません。
- **スタミナ消費量の増減・スタミナ回復**（省エネ走法・ロングスパート・
  セカンドウインド・独走態勢・緊急回復）は、実効スタミナの倍率に換算します
  （消費8%減＝スタミナ×1.08）。この扱いにすると、たとえばロングスパートは
  パワー+7%よりスタミナ−8%の方が重い長距離では**マイナス**になる、といった
  距離ごとの損得も自動的に出ます。
- **同族嫌悪**（同じおあしすっちが同レースにいると全ステータス×1.2）は、
  出走表の顔ぶれを見て**発動する馬にだけ**倍率を掛けます。ゲームが同名馬に付ける
  `#2` は種類の判定時に外します。実ログでも、同族がいる時 +0.17 / いない時 −0.05 と
  はっきり差が出ており（同族嫌悪を持たない馬には差なし）、条件付き実装で
  順位相関が 0.88→0.90 に上がりました。
- **安定感**（速度のばらつきが約半分）は平均への効果ではなく**その馬のσを下げる**
  スキルとして扱います。ただしσにはモデルの推定誤差も含まれるので、
  ゲーム側のランダム性とみなす割合（既定50%）にだけ効かせる安全側の実装です。
- **攻略本由来のハードコード（距離係数・スタミナ足切り）は全廃**。距離ごとの
  ステータス重みは実ログから学習します。

## 1. 必要なもの

- Python 3.9 以上（推奨 3.10〜3.12）
- レースログ（Discordエクスポートの .txt）

## 2. セットアップ（初回のみ）

```bash
pip install -r requirements.txt
```

## 3. 起動

```bash
streamlit run oasis_app.py
```

ブラウザが開かなければ `http://localhost:8501` へ。

### ログの読み込み元（サイドバーで選択）

| 取得元 | 説明 |
|---|---|
| 📁 **リポジトリ内**（既定） | アプリと同じ場所の `logg/` を自動で探して読みます |
| ⬆ アップロード | `.txt` をその場でドロップして学習 |
| ☁ Google ドライブ | secrets に `[gdrive]` を設定すると選べます（[DEPLOY.md](DEPLOY.md)） |

`logg/` に .txt を複数入れてもまとめて読みます。期間が重なるエクスポートを
並べて置いても、重複は自動で除外されます。

学習結果はキャッシュされるので、2回目以降の操作では待ち時間がありません。
ログを差し替えたときだけ「📚 モデル学習 / 再学習」を押してください。

## 4. 使い方

1. サイドバー **「1) モデル学習」** でログを読み込みます（既定で自動学習）。
   - **フォルダを指定すると中の .txt をまとめて読みます**（例: `logg`）。
     ファイル名・ワイルドカード（`logg/*.txt`）・フルパスも可。
   - Cloud ではドライブから自動取得します（[DEPLOY.md](DEPLOY.md)）。
   - 既定では **2026/07/28 以降**のレースだけを学習します（スコア式が変わった日）。
     それ以前は別のゲームだと思ってください。
   - 新式のレースが12件未満のときは、旧データも時間減衰つきで併用して
     とりあえず動くようにしますが、精度は落ちます（警告が出ます）。
2. **「2) 安定運用パラメータ」** で資金・リスクを設定。
3. **「🎯 予測」タブ**にレースデータを貼り付けて **「解析」**。
   ブックマークレット v2 の出力でも、**購入画面をそのままコピペ**でもOKです。
   購入画面をパッシブの説明文ごと貼ると、スキルの実数値を自動で覚えます
   （覚えた直後は「再学習」を押すと予測に反映されます）。
   ⚠ 購入画面にはレース距離・馬場が書かれていないので、**サイドバーの「3) レース条件」を
   必ず実際のレースに合わせてください**。距離が違うと結果は別物になります。
4. **推奨配分**（✅）と口数、実効EV・いずれか的中・最大損失が出ます。購入リストはコピー用。
5. レース後、**「📒 実績ログ」タブ**で実着順を入れて精算 → 成績レポートで
   予測 vs 実測（キャリブレーション）と ROI を確認。

### データの取得（ブックマークレット v2）

`oasis_bookmarklet_v2.html` をブラウザで開き、ボタンをブックマークバーへドラッグしてください。
券購入ページでクリックすると、下の形式が丸ごとクリップボードに入ります。

```
guild=... / schedule_id=... / pool=...
=== 出走馬一覧 ===
レース距離,馬場,地面,馬名,成体種,SPEED,POWER,STAMINA,コンディション,パッシブスキル1,パッシブスキル2,単勝オッズ
マイル,ダート,,メビウス,hyou,159,49,47,好調,スピードスター,マイル得意,1.0
=== パッシブ効果 ===
パッシブ,コード,説明
スピードスター,speed_star,スピードが35%上昇する代わりに、スタミナが10%低下する。
=== 3連単オッズ ===
順位,1着,2着,3着,オッズ
1,メビウス,ういえれ,うるは,12.5
```

v2 の要点は3つです。

- **パッシブ2枠**（`passive_skill` / `passive_skill_2`）の両方を取得します。
- **スキル名の辞書を持ちません**。券購入ページ自身が持つ `PASSIVE_INFO` を読むので、
  ゲームにスキルが追加されても自動で追従します（旧版はコードを手で足す必要がありました）。
- **効果の説明文**（`=== パッシブ効果 ===`）と**成体種**を出力します。説明文は
  `passive_spec.json` に蓄積されて予測の倍率に、成体種は同族嫌悪の発動判定に使われます。

手入力・他形式でも読めます。パッシブは `スピードスター / マイル得意` のように `/` 区切り
（`、` `・` `+` `|` も可、絵文字あり/なしどちらでも可）、列は `パッシブスキル1` `パッシブスキル2` に
分けても、APIコード（`speed_star` 等）を直接書いてもかまいません。
3連単オッズを別CSVで持っている場合は、サイドバー「詳細」にCSVパスを入れてください。

※ 地面（良/稍重など）はAPIが返さないため空欄になりますが、予測結果には影響しません
（レース全体に等しく効くぶんはモデル内部で相殺されるため）。

### 買い目の一括購入（ブックマークレット v2）

`oasis_buy_bookmarklet_v2.html` のボタンをブックマークバーへ入れ、券購入ページで
クリックして、予測タブの **「📋 購入リスト（コピー用）」** をそのまま貼り付けます。

```
おいら → みぃちゃん → テト x3
みぃちゃん → おいら → テト x1
おいら x5             ← 単勝
```

`→` があれば3連単（1口 10,000 rrc）、無ければ単勝（1口 1,000 rrc）として扱います。
口数は `x3` `×3` `3口` のいずれでも可、省略すれば1口。同じ行を並べた
「1行1口」形式でも自動で合算します。

解析すると買い目・口数・**合計 rrc** が出て、「内容を確認しました」に
チェックを入れるまで購入ボタンは押せません。締め切り済みのレースは 🔴 で警告します。

> ⚠️ 実際に rrc を消費します。取り消しはできません。

### 「🔬 モデルを見る」タブ

- 学習レース数・順位相関・1着的中率・σ。
- **校正チェック**: 「モデルが言う確率」と「実際に起きた率」の比較。
  実測のほうが高ければ弱気（安全側）、低ければ強気（過剰投資の危険）。
- **パッシブスキルの効き目**: 距離・馬場を選ぶと、そのレースでの効果（%）が出ます。
  出所が3種類あります。
  - 🎮 **ゲーム表記**（34種）… 券購入ページの公式データから取り込んだ確定値。
  - 📊 **実測から学習**（1種）… 粘り腰（「スタミナ不足による速度低下を20%軽減」）は
    ステータス倍率に落とせないため、実ログから効果を学習しています。

  「発動条件」列で、適性系・区間限定・同族嫌悪などの条件も確認できます。
  ゲームに新スキルが追加されても、ブックマークレットで取得して貼れば
  説明文から数値を読み取って自動で覚えます。

### 未成立スリーブ（任意）

市場が張っていない（未成立）組にも各1口だけ賭けるオプション。当たれば全プール総取りで
実効オッズが非常に高くなります。ほとんど外れ、稀に大勝ちする **+EVの宝くじ**で、
安定収益とは別物です。モデルの的中率が正しい前提なので、成績レポートで低確率帯の
校正を確認してから使ってください。

### 単勝（任意）

単勝は **1口 1,000 rrc**、**1レースで合計 100口まで**（全頭の合算です。
1頭に100口ではありません）。1口の金額は購入画面の『1口（N rrc）』から自動で読み取ります。

#### 単勝プールは「試し買い」で実測します

実ログ379レースを調べたところ、**Σ(1/最終オッズ) = 1.000**（標準偏差0.001）でした。
単勝は**控除0%の純パリミュチュエル**で、これは裏を返すと
**オッズは各馬のシェアしか表さず、プール総額の情報を一切含まない**ということです。
プールが分からないと自分の購入によるオッズ低下を計算できず、期待値を過大評価します。

そこで少額の試し買いで実測します。

1. オッズ取得ブックマークレットでデータを取る（①）
2. 好きな馬に単勝を**少しだけ**買う（3〜10口目安）
3. もう一度データを取る（③）
4. 予測タブの **「🥇 単勝：プールを実測して推奨を出す」** に ① と ③ を貼る

原理はこうです。自分が合計 Δ を入れるとプールは `P → P+Δ` になります。
**自分が買っていない**馬はその馬への投入額が変わらないので、
オッズの比が `od後/od前 = (P+Δ)/P` になり、`P = Δ / (od後/od前 − 1)` で逆算できます。
買っていない馬の数だけ独立した推定値が得られるので、中央値を取り、
ばらつきを「他の人の投票が混ざった度合い」として表示します。

推定できたら、希薄化を織り込んだ実効オッズ
`(P + 合計投入) / (その馬への投入 + 自分の投入)` で期待値を計算し、
合計EVが最大になる配分を1口ずつ決めます。プールが小さいときは希薄化が大きいので
**自動的に口数が絞られます**（テストでは同じ条件でプール25万→44口、2.5万→1口）。

> ⚠ 試し買いと再取得の間隔が空くと他の人の投票が混ざって誤差になります。
> ばらつきが大きく出たら測り直してください。

なお、オッズが 1.5（初期値）に張り付いている馬は「まだ誰も投票していない」状態です。
市場が形成される前は割安・割高の判定ができないので、締め切り前に貼り直してください。

## 5. 運用上の注意

- 出力は**モデルの的中率が正しい前提**です。まずは小さく回し、成績レポートで
  「予測≈実測」を数十レース確認してから資金を増やしてください。
- 学習データは現状 **34レース／434行**しかありません（新スコア式になってから日が浅いため）。
  ログが貯まるたびに再学習すると精度が上がります。特に**サンプルの少ないパッシブ**
  （末脚・ペース配分・セカンドウインドなど）の推定は、今はかなり粗いです。
- ゲーム側がまた計算式を変えた場合、「モデルを見る」タブの順位相関が急に落ちます。
  そのときは `学習に使う期間の開始日` を新しいアプデ日に設定して再学習してください。

## 6. exe化

Streamlitはサーバ型のため、PyInstaller でランチャ(`run_app.py`)ごと固めます。
**exeはビルドしたOS専用**です。

1. Windows: `build_exe.bat` / Mac・Linux: `bash build_exe.sh`
2. `dist/OasisYosou/` が出来ます。
3. ログ（`logg` フォルダ等）を `dist/OasisYosou/` に置いて exe を実行。
   黒いコンソール窓はローカルサーバ本体です（閉じるとアプリが止まります）。

ビルドで `ModuleNotFoundError` が出たら `oasis.spec` の `hiddenimports` に追記して再ビルド。
どうしても通らない場合は `streamlit run oasis_app.py` が確実な代替です。

## 8. よくある質問

- **Q. 学習で「対象レースが0件」になる** → 既定では 2026/07/28 以降のレースしか使いません。
  ログが古い場合は `学習に使う期間の開始日` を早めるか、新しいログを追加してください。
- **Q. 「サンプルが少ないパッシブ」の警告が出る** → そのスキルの効果推定が粗いという意味です。
  そのスキル持ちが絡む買い目は割り引いて見てください。ログが増えれば解消します。
- **Q. 数字が毎回同じ** → 再現性のためシミュレーションのシードを固定しています。
- **Q. 校正チェックで「予測 < 実測」と出る** → モデルが弱気（σが大きい）。安全側なので
  そのままでも損はしませんが、実績が20件以上貯まったら σ を少し下げると期待値が上がります。
- **Q. ログが「見つかりません」** → 相対パスは**アプリのフォルダ**が基準です。
  サイドバーに解決後の絶対パスが出るので確認してください。
